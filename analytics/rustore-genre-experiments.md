# Программа жанровых экспериментов для RuStore (A, B, C)

Дата: 2026-11-18. Статус: план. Уверенность в выборе жанров — низкая/средняя: решение должно принять тестирование.

## Почему уходим от чистых головоломок
RuStore, I кв. 2026: головоломки — 29% скачиваний и 8% платежей; RPG — 9% и 28%; шутеры — 30% платежей, стратегии — 15% (данные RuStore в пересказе СМИ, факт). Доля платежей ≠ выручка на игру: в платящих жанрах вероятно доминируют гиганты (оценка). Рынок мобильных игр РФ, 2025: 61,6 → 89,8 млрд ₽ (+45,9%, оценка VK в пересказе издателя).

Поправки к ранним выводам: доля платежей RPG не доказывает выгоду инди-RPG; покупки первого дня в MMORPG не обосновывают оффер в первой сессии; idle-RPG не дешевле по контенту; для B и C мета — часть проверяемой ценности, тест «без меты» недостаточен.

## Этапы
0. Smoke test: Android export, РСЯ (rewarded: показ, отмена, выдача награды), RuStore Billing (покупка, восстановление), доставка событий после офлайна, сворачивание/kill процесса, миграция сохранений. Поддержка Google Play Billing в Godot ≠ совместимость с RuStore — при отсутствии плагина оценить Android bridge.
1. Удовольствие: вертикальный срез, 8–12 внешних тестеров.
2. Возвращаемость: контент и минимальная мета на несколько дней, платный трафик.
3. Экономика: реальные показы и покупки.

## Архитектура
Godot 4, GDScript, 2D, Compatibility renderer, проверка на реальном слабом устройстве.
```
shared/{analytics,save_system,consent,ads,billing,remote_config,diagnostics}
experiments/{a_survivor,b_merge_workshop,c_idle_caravan}
```
Общие интерфейсы, отдельные сборки; без универсального gameplay-фреймворка. Offline-first, без аккаунтов; remote config — версионированный JSON по HTTPS с локальными дефолтами; валидация покупок — до реальных продаж; push не нужен на первом цикле. ML в MVP не нужен; полезна автоматизация: симуляция экономики, кластеризация отзывов и playtest-заметок (с проверкой человеком). 152-ФЗ; GDPR — проверить применимость.

## Аналитика
Общие события: first_open, consent_updated, tutorial_step, session_start, session_summary, progression_unlock, rewarded_offer, rewarded_result, purchase_offer_view, purchase_start, purchase_result, save_error.
Поля: experiment_id, build_version, balance_version, variant_id, acquisition_source, device_tier. Варианты назначаются стабильно; разные балансы не смешивать в одной когорте.

Трактовка: 8–12 тестеров — крупные проблемы, не retention; 300–500 установок — screening крупных различий, не редких покупок; D7 ждать полностью; маленькую когорту не дробить на A/B. Пороги D1/D7 — внутренние ориентиры (западные источники гибридказуала), для РФ пересчитать.

Деньги: Contribution LTV = доход от рекламы + IAP после удержаний − переменные расходы; сравнивать с фактическим CPI по источнику и версии. Доход D7 ≠ полный LTV.

## Бюджет и порядок
До 5 тыс. ₽ на ассеты на срез; трафик траншами по 3–5 тыс. ₽ на концепт, следующий — после проверки качества аудитории. Время считать по внутренней ставке.
Порядок: smoke test → срез A → playtest A → срез B → playtest B, сравнение → C только при оставшейся гипотезе и бюджете.
